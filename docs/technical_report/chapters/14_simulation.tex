\chapter{Simulation Environment}
\label{ch:simulation}

\section{Purpose}

The simulation module generates realistic synthetic energy data so the entire system---ML pipeline, optimization engine, dashboard---can be developed and tested independently of physical hardware. The simulator publishes data via MQTT in the same JSON format as the ESP32, making the backend hardware-agnostic.

\section{Profile Generators}

\subsection{Weather Profile}
Clear-sky irradiance is computed using solar geometry for Meknès (latitude 33.9°N). Temperature follows a sinusoidal daily cycle peaking at 15:00. Cloud cover is applied as a configurable multiplicative factor with Gaussian noise for variability.

\subsection{PV Production Profile}
PV power is derived from irradiance and temperature using Equation~\ref{eq:pv_power}, with 2\% Gaussian noise to simulate mismatch and dust effects.

\subsection{Load Consumption Profile}
Building load follows empirical hourly shape curves for weekday and weekend patterns, with base load (refrigerator, standby), variable load (lighting, TV, cooking), AC load (summer afternoons), and flexible loads (water heater, washing machine, water pump at fixed default times).

\section{Anomaly Injection}

The simulator injects controlled anomalies into the synthetic data: nighttime consumption spikes (3--5$\times$ normal), daytime load surges (2.5--4$\times$ normal), and PV production drops during clear-sky conditions. These anomalies serve as ground truth for evaluating the anomaly detection module.

\section{Dataset Summary}

The primary dataset covers 365 days (June 2025 -- May 2026) with seasonal variation: 35,040 rows at 15-minute resolution, 26 columns, with 260 time steps flagged as anomalous. The dataset is reproducible (seed = 42) and clearly labeled as synthetic.
